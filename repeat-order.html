Repeat Order: turning a hidden shortcut into a growth lever

Context

After launching the new Mercadona Online website and apps, the team started focusing more on improving business performance.

One of the areas we looked at was the cart experience, and Repeat Order stood out as an interesting opportunity.

I led the design work from research to validation, working closely with Product and Engineering throughout the two sprints.

What is Repeat Order?

Repeat Order was clearly the fastest option, especially for customers doing a similar shop every week. But it wasn’t being used as much as we expected.

Regular customers could fill their cart in three main ways:

  • My regular products — adding products one by one
  • Browse the catalogue — also adding products individually
  • Repeat Order — copying a previous order into the cart
The opportunity

Could we get more existing customers to use Repeat Order?

We saw that orders made through Repeat Order had an average ticket around €2 higher than orders built manually.

That made Repeat Order an interesting growth opportunity. If we could get more existing customers to use it, there was a potential benefit for both sides: less effort for customers and a higher average ticket for the business.

Why weren’t people using it?

The main issue was a lot of people either couldn’t find it or didn’t feel confident using it.

I ran research sessions with 20 regular customers in a Mercadona store.

I first interviewed them about how they usually shopped online, then gave them a task using the existing experience to see whether they could find and use Repeat Order.

A few patterns came up quickly:

  • 40% couldn’t find Repeat Order
  • 20% didn’t know it existed
  • 60% weren’t sure what would happen after tapping it
  • 60% thought it would send them straight to checkout, without giving them a chance to edit the cart
Hypothesis and goal

If Repeat Order was easier to find and clearer to understand, more customers would use it.

The PM set the business goal: +€0.15 on the average ticket across all orders.

My job was to understand what was stopping customers from using Repeat Order and design the smallest changes that could improve adoption.

Exploring the journey

The aim wasn’t to redesign the whole flow. It was to make Repeat Order easier to notice and easier to understand.

I ran a workshop with Product and Engineering to identify where Repeat Order could be easier to discover.

We focused on three key touchpoints:

  • Home — make Repeat Order visible before customers start rebuilding their cart
  • Order History — make previous orders easier to reuse
  • Order Detail — move the action to a more visible position and make the outcome clearer

The same experience was adapted for iOS and Android using native components and interaction patterns.

Testing

I created mobile prototypes and tested the new Repeat Order experience with another 10 customers in a Mercadona store.

For each touchpoint, we had a specific question.

Home. Would people notice Repeat Order before starting to build their cart manually? All 10 participants used the Repeat Order button on Home as their entry point into the flow.

Order History. Would people understand that they could repeat any previous order? 7 of 10 participants opened the order card first instead of using the Repeat Order action directly. This showed us that the card was still the more natural entry point for most customers.

Order Detail. Would moving the action higher make it easier to find? Moving Repeat Order to the top made the action easier to find, without requiring customers to scroll through the order first.

Across the flow, we also checked whether customers understood that Repeat Order created an editable cart rather than taking them directly to payment.

MVP — Home

Make Repeat Order visible earlier

We added a Repeat order button to the latest-order card on Home. It was always visible, while the second action changed depending on the order status: Rate until the order was rated, then View order.

This gave customers access to Repeat Order before they started browsing or adding products manually.

We also added a short “What’s new” message to explain the feature and make one thing very clear: you can still edit your cart after repeating an order.

That directly addressed one of the biggest concerns we had seen in research.

MVP — Order History

Give customers another way to access Repeat Order

We added a Repeat order action to completed orders inside Order History. The idea was to make previous purchases easier to reuse directly from the list.

During testing, however, 7 of 10 participants opened the order first instead of using the Repeat Order action straight away.

That showed us that, for many customers, Order History was still more of a way to inspect a previous order than to immediately repeat it. This made the Order Detail experience even more important.

The Order History change shipped on web, but not on the apps.

MVP — Order Detail

Move the action to where people actually look

The Repeat Order button was originally at the bottom of the Order Detail page, below the receipt.

We moved it to the top of the page, inside the order status card, and made it the main action.

It was a small change, but it meant customers no longer had to scroll through the full order before finding it.

What shipped

We didn’t manage to ship every change across every platform.

Web
Home · Order History · Order Detail
Apps
Home · Order Detail

The main gap was Order History on apps, which didn’t make it into this release.

We had underestimated the implementation effort, and priorities changed during the project.

Looking back, I would have scoped the first release more tightly and aligned earlier on what we could realistically ship across platforms.

Results

After launch, we saw more customers using Repeat Order, and the business target was reached.

+€0.15
On the average ticket

We also saw strong improvements across the Repeat Order journey:

70.7%
Purchase conversion, from 34.6%
9.03%

16 min
Time to purchase, from 34 min

The changes made Repeat Order easier to discover and helped customers complete their purchase faster and with less drop-off.

What I learned

The feature itself didn’t need a major redesign.

The main problem was that customers weren’t seeing it, or they weren’t sure what would happen if they used it.

A few relatively small changes in visibility, hierarchy and copy made the experience much easier to use.

The other learning was around scope. We tried to cover several touchpoints across web, iOS and Android in two sprints, and not everything made it into the release.

If I did this project again, I would:

  • scope the first release more tightly
  • agree earlier on what could realistically ship across platforms
  • measure each touchpoint separately to understand which one was contributing most to the result
